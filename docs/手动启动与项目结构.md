## 二、环境准备

### 2.1 必备软件

- **JDK 17**（`java --version` 应为 17.x）
- **Maven 3.9+**（`mvn --version`）
- **Docker**（用于快速起中间件，也可本地安装）
- **微信开发者工具**（前端调试用）

### 2.2 中间件端口约定

| 中间件 | 端口 | 备注 |
|---|---|---|
| MySQL | 3306 | 库名 `ai_smart_campus`，用户 `root` / 密码 `123456` |
| Redis Stack | **6380**（非默认 6379） | 用 Redis Stack（含 RediSearch 模块，做向量存储） |
| RabbitMQ | 5672（管理台 15672） | 默认账号 `guest/guest` |
| MinIO | 9001（API 9000） | 默认 `minioadmin/minioadmin` |

> ⚠️ 端口必须与上表一致，因为 `application.yml` 默认按此配置。如本机端口冲突，可在启动时用环境变量覆盖（见第 4 节）。

## 三、启动中间件

### 3.1 用 Docker 一键拉起（推荐）

```bash
# MySQL 8.0
docker run -d --name mysql-smart-campus \
  -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD=123456 \
  mysql:8.0

# Redis Stack（含 RediSearch 向量模块）
docker run -d --name redis-stack-smart-campus \
  -p 6380:6379 \
  redis/redis-stack-server:latest

# RabbitMQ（含管理台）
docker run -d --name rabbitmq-smart-campus \
  -p 5672:5672 -p 15672:15672 \
  rabbitmq:3.12-management

# MinIO
docker run -d --name minio-smart-campus \
  -p 9000:9000 -p 9001:9001 \
  -e MINIO_ROOT_USER=minioadmin \
  -e MINIO_ROOT_PASSWORD=minioadmin \
  minio/minio:latest server /data --console-address ":9001"
```

### 3.2 初始化数据库

项目自带建表脚本，**首次启动时应用会自动检测并初始化用户数据**，但表结构需提前建好：

```bash
# 方式一：用 mysql 客户端执行
mysql -uroot -p123456 < sql/init.sql

# 方式二：进入 MySQL 容器执行
docker exec -i mysql-smart-campus mysql -uroot -p123456 < sql/init.sql
```

> `sql/init.sql` 含 `t_user`、`t_conversation`、`t_message`、`t_announcement`、`t_club` 等全部建表语句。
> 首次启动后 `DataInitializer` 会自动插入 5 个默认账号（学号 `2307020101~103`、`2307020104`、`2307020105`，密码均为 `123456`）。

### 3.3 验证中间件就绪

```bash
# 端口检查（看到 LISTENING 即可）
netstat -ano | grep -E ":3306 |:6380 |:5672 |:9001 "
```

## 四、配置 AI API Key

项目通过**环境变量**注入密钥（`application.yml` 中以 `${VAR:default}` 读取）。启动前必须设置：

```bash
# Linux / macOS / Git Bash
export AI_API_KEY=你的DeepSeek_API_Key
export AI_BASE_URL=https://api.deepseek.com
export SILICONFLOW_API_KEY=你的硅基流动_API_Key
```

```powershell
# Windows PowerShell
$env:AI_API_KEY="你的DeepSeek_API_Key"
$env:AI_BASE_URL="https://api.deepseek.com"
$env:SILICONFLOW_API_KEY="你的硅基流动_API_Key"
```

```cmd
:: Windows CMD
set AI_API_KEY=你的DeepSeek_API_Key
set AI_BASE_URL=https://api.deepseek.com
set SILICONFLOW_API_KEY=你的硅基流动_API_Key
```

| 变量 | 必填 | 默认值 | 用途 |
|---|---|---|---|
| `AI_API_KEY` | ✅ Chat 必须 | `sk-demo-key` | DeepSeek 对话模型 |
| `AI_BASE_URL` | ✅ | `https://api.deepseek.com` | 对话模型地址 |
| `SILICONFLOW_API_KEY` | ✅ Embedding 必须 | 空 | 硅基流动向量模型（RAG/语义搜索） |
| `MYSQL_USER` / `MYSQL_PASSWORD` | — | `root` / `123456` | 数据库账号 |
| `REDIS_HOST` / `REDIS_PORT` | — | `localhost` / `6380` | Redis 连接 |
| `RABBITMQ_HOST` / `_PORT` | — | `localhost` / `5672` | MQ 连接 |
| `MINIO_ENDPOINT` / `_ACCESS_KEY` / `_SECRET_KEY` | — | `localhost:9001` / `minioadmin` x2 | 对象存储 |

> ⚠️ 若未设置 `AI_API_KEY`，应用仍能启动，但调用 `/api/chat/*` 会返回 `{"code":500,"message":"服务器内部错误"}`。

## 五、编译与启动后端

### 5.1 编译打包

```bash
cd ai-smart-campus
mvn clean compile                    # 仅编译验证
mvn clean package -DskipTests        # 打包（跳过测试，AI测试需联网）
```

产物：`campus-core/target/campus-core-1.0.0-SNAPSHOT.jar`

### 5.2 启动（三选一）

**方式 A：jar 包启动（推荐，生产式）**

```bash
java -jar campus-core/target/campus-core-1.0.0-SNAPSHOT.jar
```

**方式 B：Maven 直接运行**

```bash
mvn spring-boot:run -pl campus-core
```

**方式 C：带环境变量一行启动**

```bash
AI_API_KEY=sk-xxx AI_BASE_URL=https://api.deepseek.com \
SILICONFLOW_API_KEY=sk-xxx \
java -jar campus-core/target/campus-core-1.0.0-SNAPSHOT.jar
```

启动成功标志（日志中出现）：

```
Tomcat started on port 8088 (http) with context path ''
Started CampusApplication in ~11 seconds
```

### 5.3 端口冲突处理

默认端口 **8088**。若被占用：

```bash
# 查看占用进程
netstat -ano | grep ":8088 "
# 终止（Windows）
taskkill //PID <PID> //F
```

或临时改端口：`java -jar xxx.jar --server.port=8090`

**前端设计要点**：
- **无第三方 UI 库**，全部自定义，全局样式靠 `app.wxss` 的 CSS 变量（设计令牌）一处统管。
- **SSE 流式**：`utils/api.js` 的 `sseRequest()` 用 `wx.request` 的 `enableChunked` 实现增量解析。
- **Markdown 自渲染**：`util.js:renderMarkdown()` 解析子集，`chat-bubble` 组件渲染为结构化 WXML。
- **统一带 Token**：所有请求（含 SSE/上传）自动从 `storage.getLoginState()` 取 JWT 加到 `Authorization` 头。
- **响应错误码约定**：HTTP 状态恒为 200，业务结果看 `body.code`（200 成功 / 401 未登录 / 403 无权限 / 404 不存在 / 500 服务器错误）。

## 九、核心数据流（对话为例）

```
小程序 chat-detail
  │  POST /api/chat/send  (Authorization: Bearer <jwt>, body: {message, conversationId})
  ▼
TokenInterceptor  →  解析 JWT → UserContext.set(当前用户)  →  放行
  ▼
ChatController.send
  │  currentUserId() 取当前用户（null则抛401，不再兜底用户1）
  │  conversationId 为空 → createConversation(userId) 新建
  ▼
ChatService.chatStream(convId, msg, userId)
  │  loadOwnedConversation(convId, userId)  ← 校验归属：不属于该用户抛403
  │  保存 user 消息 → ChatClient SSE 流式调用 DeepSeek
  ▼
返回 Flux<String> → 逐 chunk 下发 → 小程序 onChunk 拼接渲染
```

**对话隔离保证**：`t_conversation.user_id` + `ChatService.loadOwnedConversation()` 强制校验，任何 `getMessages`/`deleteConversation`/`chat*` 操作前先验「会话是否属于当前登录用户」，否则 `403 无权访问该会话`。

## 十一、常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| `Port 8088 was already in use` | 端口被占 | `taskkill` 占用进程，或 `--server.port=8090` |
| `/api/chat/*` 返回 500 | `AI_API_KEY` 未设置 | 按第 4 节设置环境变量后重启 |
| `HikariPool ... Connection refused` | MySQL 未起或端口不对 | 启动 MySQL，确认 3306 |
| `Redisson ... connection refused` | Redis Stack 未起 | 启动 Redis Stack，确认 **6380** |
| 登录返回 `学号/工号或密码错误` | 学号写错（非 `2307020101`） | 用种子账号 `2307020101~105` / `123456` |
| 前端请求 401 | JWT 过期或未带 | 小程序重新登录；后端拦截器对 `/api/**` 强制鉴权 |
| 前端中文消息后端报 UTF-8 错 | curl 在 Windows GBK 编码（仅命令行测试） | 小程序真机/开发者工具发标准 UTF-8，不受影响 |
